Fix It — Action List

  1. Verify the Marketo form loads for real visitors (mktoForm_3151). The audit browser saw the form container with zero fields. Open the page in a normal browser with no script blocking; if the fields are missing there too, the page's lead-capture path is broken. The Accessibility Testing page shows the identical symptom (same form ID mktoForm_3151, zero fields, MktoForms2 never defined), so this looks like one shared form. A likely cause is the Marketo script being held back until cookie consent is given, which would be expected behavior; confirm in a normal session.
  2. Add Service schema to the page's existing JSON-LD @graph (customer journey testing offering, provider = the Applause Organization). Ready-to-paste JSON-LD is in Recommended Schema above; fill in dateModified from CMS metadata first.
  3. Fix heading hierarchy. Make the three benefit-card headings H3s under their H2 (or demote the H2), and make the footer headings non-heading elements or H2/H3.
  4. Add a semantic <main> element wrapping the page content between the nav and the footer (a Divi theme/template change, so it likely fixes every page at once).
  5. Add related-service links in the body (for example from the "Actionable Feedback" list to UX testing, payment testing and in-store testing).
  6. Optional, for later: once an FAQ is added (see the content audit's P2), generate FAQPage schema for it and expand the Organization entity with sameAs and a description.
